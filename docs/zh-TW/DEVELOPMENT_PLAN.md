# re-Anomaly 專案開發計畫

本文件概述了 re-Anomaly 專案為期 10 週的開發策略。該計畫旨在從基礎建設過渡到進階模型實驗，最後實現生產等級的部署。

## 開發階段概述

開發過程分為五個階段，每個階段持續兩週。時間表重點在於建立穩健的模組化框架、實現最先進的異常檢測頭、執行大規模預訓練，以及針對 NVIDIA RTX 4090 硬體優化實際部署。

## 第 1 階段：基礎建設 (第 1-2 週)

本階段的主要目標是建立核心基礎設施與資料處理能力。

- 專案設定 (已完成)
- 骨幹網路載入器實現：
    - DINOv2 整合，用於高品質特徵提取
    - DINOv3 (iBOTv2) 支援，獲取最新的自監督表示
    - PixIO 風格的 Vision Transformer 整合
- 基礎資料管線：
    - 高效的影像載入與轉換
    - 支援標準異常檢測資料集 (如 MVTec AD, VisA)
- 設定系統：
    - 實現 Hydra 以進行靈活的實驗管理
    - 模型、資料與訓練的標準化設定架構 (Schemas)

## 第 2 階段：核心組件 (第 3-4 週)

本階段專注於各種異常檢測架構的實現，以及支援訓練/評估的基礎設施。

- 檢測頭實現：
    - PatchCore: 實現記憶庫與 k-最近鄰 (kNN) 搜尋
    - MSFlow: 用於密度估計的多尺度正規化流
    - SimpleNet: 基於特徵判別的簡化架構異常檢測
    - SALAD: 用於增強異常定位的雙流架構
    - Linear Head: 用於線性探查 (Linear probing) 的基準實現
    - FastFlow: 基於正規化流檢測的參考基準
- 訓練管線：
    - 支援多骨幹與多檢測頭的統一 Trainer 類別
    - 整合日誌工具 (如 TensorBoard 或 WandB)
- 評估指標：
    - AUROC (接收者操作特徵曲線下面積)
    - 不同閾值下的 Recall (召回率) 與 Precision (精確率)
    - 像素級與影像級指標計算

## 第 3 階段：預訓練 (第 5-6 週)

利用 300 萬張影像資料集，本階段專注於領域特定與通用目的的預訓練，以增強特徵表示。

- MAE 預訓練：
    - 使用 300 萬張影像資料集進行 PixIO 風格的遮罩自編碼器 (MAE) 預訓練
    - 設定遮罩比例與重建損失
- DINO 領域自適應預訓練 (DAPT)：
    - 使用領域特定的工業資料微調 DINO 模型
    - 優化對比損失與聚類損失
- 預訓練權重整合：
    - 標準化整個框架的權重載入機制
    - 驗證表示品質的提升

## 第 4 階段：實驗 (第 7-8 週)

系統性地探索不同的模型組合與消融實驗，以確定最佳配置。

- Plan A: PatchCore 基準
    - 在所有目標資料集上對 PatchCore 性能進行基準測試
- Plan B: HLSIS 雙流架構
    - 實現並測試高階與語義資訊協同 (High-Level and Semantic Information Synergy)
- Plan C: PixIO + Linear
    - 評估 PixIO 表示與極簡線性檢測頭的結合
- Plan D: MSFlow + HGAD
    - 將多尺度流與層次分組異常檢測 (Hierarchical Grouping Anomaly Detection) 相結合
- 消融實驗 (Ablation Studies)：
    - 分析骨幹網路對檢測準確度的影響
    - 預訓練資料量對最終性能的影響
    - 不同檢測頭架構的比較

## 第 5 階段：優化與部署 (第 9-10 週)

生產使用的最終準備，專注於推論速度與部署基礎設施。

- ONNX 導出：
    - 將 PyTorch 模型轉換為 ONNX 格式以支援跨平台
    - 驗證導出後的數值一致性
- Triton 伺服器整合：
    - 為 NVIDIA Triton Inference Server 開發模型儲存庫
    - 設定動態批次處理 (Dynamic batching) 與模型實例
- 性能優化：
    - TensorRT 加速，針對 GPU 進行特定優化
    - 量化 (FP16/INT8) 以降低延遲與記憶體佔用
- 生產測試：
    - 在目標硬體 (RTX 4090) 上進行端到端延遲測試
    - 持續負載下的穩定性測試

## 風險評估

- 資料品質：300 萬張資料集中的雜訊或缺乏多樣性可能影響預訓練效果。緩解措施：實施嚴格的資料清洗。
- 硬體限制：大規模預訓練可能超出 RTX 4090 記憶體。緩解措施：使用梯度累加與混合精度訓練。
- 架構複雜性：整合多個多樣化檢測頭可能導致程式碼維護問題。緩解措施：嚴格遵守模組化設計模式。
- 時間表壓縮：第 4 階段實驗可能發現需要進一步修改架構。緩解措施：及早優先處理最有潛力的計畫。
